Get started

Setup & run

Prepare your project and agent once. You will build and run your app from stage 2 onward. Running locally, backing up and publishing are three separate things; only the first two are needed unless your course asks for a public link.

What you need

  • A Bash terminal: Terminal on macOS or Linux; on Windows, Git Bash (installed with Git for Windows) or WSL. PowerShell and Command Prompt cannot run bash run_app.sh.
  • git, and Python 3.10 or newer. Node.js 20 or newer too, if you and your agent choose a JavaScript app.
  • An AI coding agent that can read and edit your project folder and has a Plan mode.
  • The starter, from Data & files, unzipped into a folder of its own.

Plan mode and implementation mode

Every design discussion in stages 2–6 happens in Plan mode {{help plan-mode}}: the agent proposes and compares options without changing files. You choose, write down why, and only then switch to implementation mode {{help implementation-mode}} to build. The guide cannot switch modes for you.

1. Set up with your agent

  1. Open the starter folder in your agent.
  2. Give it this starting prompt. It works in the agent's normal mode, because setup is not a design discussion. 
    Read AGENT_BRIEF.md and follow it for this whole project.
My scenario is your scenario, file data/your CSV file.
Inspect the project (README.md, SETUP.md, DECISIONS.md, load_data.py) and the data (data/README.md and my CSV). Summarise in a few sentences what the project contains and what the columns of my CSV are. Do not calculate the true mean for me.
Then explain what setup this project needs on my computer, recommend one simple stack that can run my app locally (following my course's tools if I name them), and wait for my OK before installing anything.
After I agree, prepare the environment, explaining each command before you run it and what its output means. Do not design or build the app yet: I will brainstorm the design with you in Plan mode in stage 2.
  3. Read the summary yourself. Check it against data/README.md.
  4. Confirm the data loads: python3 load_data.py data/your CSV file (in Git Bash, the command may be python).

2. Run your app: bash run_app.sh

Your agent writes run_app.sh when it builds your first app in stage 2 (the build prompt asks for it). From then on, you start the app yourself:

  1. Where: a Bash terminal whose current folder is your project (the folder with run_app.sh). Check with ls.
  2. Command: bash run_app.sh
  3. Open: the address it prints, usually http://localhost: followed by a port number, in your browser.
  4. Stop: press Ctrl+C in that terminal.

If you need the launcher before stage 2 or it goes missing, ask in implementation mode:

Ask your agent Implementation mode

Write run_app.sh as AGENT_BRIEF.md describes: a Bash script, saved with LF line endings, that starts my app on this computer from the project folder. Then tell me where to run it, the exact command, the address to open and how to stop it. Do not run it for me.

3. Back up with git

Create a new, empty repository on GitHub (or your course's host). Do not add a README; the starter has one. Then, in your project folder:

git init -b main
git add .
git commit -m "Starter"
git remote add origin https://github.com/<username>/<repository>.git
git push -u origin main

Commit and push at the end of every stage. A commit is not a backup until it is pushed. Never commit passwords, tokens or API keys.

4. Publish Optional

Running locally is enough unless your course requires a public app. If it does, publish only once your app exists, and only the app you built.

Choosing a host and checking the link
  • A browser-only app (HTML and JavaScript, sampling done in the page) can be served by GitHub Pages: repository Settings → Pages, deploy from branch main. GitHub Pages serves files only; it cannot run a Python or Node server.
  • An app that needs a Python or Node server needs a host that runs one, such as the host your course recommends, or must be converted to run in the browser. Ask your agent in Plan mode which option fits your stack.
  • The published app must really work: live sampling, repeated sampling and your challenge controls must run there. Static exported results or screenshots do not satisfy these interactions.
  • Check it in a private (incognito) window: it must load without signing in. Then put the link on the first line of your README.md.

Troubleshooting and reporting errors

When something fails, give your agent: the command you ran, the folder you ran it in, and the first error line (copy it as text, not a screenshot). Ask it to explain the cause before changing anything.

bash: run_app.sh: No such file or directory

You are in the wrong folder, or the launcher has not been written yet. Run ls; if run_app.sh is not listed, cd into your project folder or ask your agent to write it.

\r, $'\r': command not found or “bad interpreter”

The script has Windows line endings. Ask your agent to save run_app.sh with LF line endings. The starter's .gitattributes keeps them LF in git.

“python3: command not found” on Windows

In Git Bash the command is often python, or py. Tell your agent which one works so run_app.sh uses it.

“Address already in use” or the port is busy

An earlier copy is still running. Stop it with Ctrl+C in its terminal, or ask your agent to make the launcher choose a free port.

The page is blank or shows no data

Open your browser's developer console (F12) and copy the first error into your agent. Check that the data path in your app is relative to the project, for example data/your CSV file.

Windows: which terminal?

Use Git Bash or WSL. In Git Bash, your C: drive is /c/, so a project in Documents is at /c/Users/<you>/Documents/<folder>. In WSL, keep the project inside your Linux home folder for speed.
